# Чек-лист подготовки LeadFlow к портфолио

Актуально на 25 октября 2026 года. Документ начинался как инвентаризация перед релизом и был
обновлён результатами technical QA и согласованного финального review. Итог review — **PASS**
локального portfolio package без оставшихся actionable P0/P1/P2. После review владелец отдельно
разрешил публикацию исходников в публичном GitHub-репозитории `leadflow`.

## Что уже готово

- Основной сценарий LeadFlow реализован: публичная заявка, защищённый кабинет менеджера, список, поиск и фильтр, карточка, смена статуса и история.
- PostgreSQL остаётся единственной базой приложения; миграции обязательны при запуске.
- Адаптер Yandex AI Studio, фоновой worker, состояния разбора, ручная коррекция и retry реализованы. Без ключа приложение стабильно показывает `not_configured`; live Yandex не проверялся.
- Durable outbox Telegram и два n8n workflow реализованы. Реальный n8n 2.44.6 прошёл CLI-импорт, ручной fixture E2E и срабатывание расписаний на отдельной PostgreSQL-базе. Использовалась только loopback-фикстура; сообщений в живой Telegram не было.
- Последние результаты: backend — `54 passed` на PostgreSQL 17.11, Ruff и compileall без ошибок; frontend — свежий прогон `24 passed` и успешная production-сборка.
- Текущий браузерный путь повторно пройден. AI-панель и keyboard focus сохранены в точном `390×844`, DPR 1, без horizontal overflow; 200% reflow-эмуляция прошла, native Chrome zoom остаётся непроверенным.
- Compose/Docker-конфигурация существует, но фактический Docker runtime в проверенной среде отсутствовал; локальный Windows-эквивалент не заменяет проверку чистого Docker-развёртывания.
- В начале release-прохода ветка `main` не имела коммитов или remote; initial commit готовится локально, а публикацию выполняет координатор.

## Два уровня готовности

Текущий запрос — локальный portfolio package: reviewable код, кейс, curated screenshots и воспроизводимый локальный запуск. Для него не обязательны Docker runtime, HTTPS, публичный hosting, live Yandex/Telegram или demo-видео, если ограничения описаны честно.

Публичный hosted release приложения — отдельный будущий уровень. Только для него обязательны целевая Docker/hosting-проверка, production security, публичный URL и выбранные live-интеграции. Текущая авторизация относится к публикации исходников, а не к hosting или включению внешних сервисов.

### 6. Принять решение по live Yandex AI

Для включения потребуются введённые локально `YANDEX_API_KEY`, `YANDEX_MODEL_URI` и согласованный лимит расходов. Ключ нельзя передавать через Git, документацию или публичный чат.

Если live-интеграция входит в релиз:

- [ ] Отправить только 20–30 новых синтетических описаний разной сложности; старые заявки автоматически не обрабатывать.
- [ ] Измерить отдельно качество `service`, `budget`, `timeframe` и подтверждающих цитат: точность, корректные `null`, неоднозначные формулировки, диапазоны и валюты.
- [ ] Зафиксировать latency, ошибки, retry и поведение при недоступности/лимитах провайдера.
- [ ] Проверить ручную коррекцию, optimistic revision conflict, защиту ручного результата и явный повторный разбор.
- [ ] Опубликовать только измеренный результат выборки и её состав; не обещать гарантированную точность модели.
- [ ] Подтвердить, что провайдеру уходит описание заявки, но не отдельные поля имени/телефона. Учесть, что пользователь может сам включить контактные данные в текст описания.

## Что блокирует публикацию, а что можно отложить

Локальный portfolio package технически собран: README, кейс, demo script, пять curated screenshots,
repository hygiene/link check и финальный review готовы. Hosting, Docker runtime, HTTPS, live
Yandex/Telegram и видео для этого режима не требуются. Публичная GitHub-публикация исходников
разрешена; создание репозитория и push выполняет координатор.

Блокирует публичный релиз:

- решение о формате и целевой среде;
- безопасный первый Git-коммит и credentials check;
- чистое развёртывание на выбранной платформе;
- production Origin/cookies/HTTPS/proxy и доступный manager URL;
- очистка demo-данных, новые credentials и rate-cap;
- native zoom/screen-reader проверка в согласованном объёме и повтор affected regression уже на целевой среде;
- отдельное разрешение на deployment/hosting, если он будет добавлен; публикация исходников уже разрешена.

Условные блокеры:

- Yandex credentials, бюджет и live-проверка нужны только если AI заявляется как подключённый live;
- Telegram bot/chat и live-доставка нужны только если уведомления заявляются как подключённые live.

Можно отложить после MVP:

- Bitrix24;
- несколько компаний, ролей или менеджеров;
- Redis/shared rate limiter для горизонтального масштабирования;
- расширенные observability/analytics;
- публичный tunnel для локальной машины;
- hosting, домен и demo-видео, пока выбран локальный portfolio package;
- дальнейшая оптимизация AI сверх измеренной release-выборки.

## Что потребуется от владельца проекта

- для текущей публикации выбран public-репозиторий `leadflow`; лицензия не выбрана и не добавляется;
- только если будет hosted release: хостинг, домен и месячный бюджет;
- решение: live или disabled для Yandex и Telegram;
- Yandex key/model URI и лимит расходов — только через локальную конфигурацию, если выбран live;
- Telegram bot/chat и публичный manager URL — только через локальную конфигурацию, если выбран live;
- правила demo-данных: состав, срок хранения, сброс и лимиты;
- отдельное согласие потребуется только для будущего deployment/hosting или подключения live-интеграций.

## Критерий готовности

LeadFlow готов к публикации, когда обязательные пункты выбранного режима закрыты воспроизводимыми
результатами, в репозитории и demo-данных нет секретов/PII, release candidate разворачивается с нуля,
восстанавливается из backup, проходит mobile/keyboard-регрессию, а пользователь отдельно разрешил
публикацию после завершённого финального review. Для текущего честного локального portfolio-режима
это разрешение получено; hosted release остаётся отдельным этапом.
