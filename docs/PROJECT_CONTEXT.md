# Контекст проекта

## Зачем строим

Портфолио должно содержать три убедительных vibe-coded проекта для трудоустройства в РФ. Первый проект — LeadFlow: небольшой, но production-minded сервис заявок ремонтной компании.

## Текущий MVP

- Публичная адаптивная форма создаёт заявку без регистрации.
- Одна компания и один создаваемый вручную менеджер.
- Защищённый кабинет: вход, список и поиск заявок, карточка заявки, смена статуса и история статусов.
- Повторная отправка формы не должна создавать дубль.
- PostgreSQL, SQLAlchemy и Alembic; React + TypeScript + Vite; FastAPI.
- Production-like локальный контур: единый origin `http://localhost:8080`, `/api` проксируется в backend.
- HttpOnly cookie-сессия, проверка `Origin` для небезопасных запросов и ограничение частоты входа/публичной отправки.
- Асинхронное извлечение из описания заявки через Yandex AI Studio: вид услуги, бюджет и срок. Менеджер видит состояние обработки, может исправить значения вручную и повторить неудачную обработку.
- Интеграция AI опциональна: без ключа и URI модели заявка получает понятное состояние `not_configured`, а основной путь приёма и обработки заявок продолжает работать.
- Telegram-уведомления опциональны: n8n по расписанию вызывает защищённый внутренний dispatch endpoint для новых заявок и одного напоминания через 30 минут. Backend владеет durable outbox, дедупликацией, retry и отправкой в Telegram; n8n не содержит бизнес-логику доставки.
- Без bot token/chat id уведомления выключены, workflows остаются неактивными, а приём заявок и кабинет продолжают работать.

## Не входит в текущий scope

Интеграция Bitrix24. Массовая автоматическая обработка ранее созданных заявок также не входит в текущий этап. Публичный tunnel для локального n8n или LeadFlow не создаётся без отдельного запроса.

## Продуктовые ориентиры

Интерфейс спокойный, собранный и человечный; не SaaS-лендинг и не декоративная CRM. Основной пользовательский путь должен уверенно работать на телефоне. Детали дизайна находятся в `PRODUCT.md` и `DESIGN.md`.

## API и безопасность

Точный исполняемый контракт определяется backend OpenAPI. Стабильные правила:

- все пути начинаются с `/api`;
- браузер всегда обращается по относительным URL и отправляет cookies;
- production origin — `http://localhost:8080`;
- dev frontend — `http://127.0.0.1:5173`, API — `http://127.0.0.1:8000` через Vite proxy;
- cookie сессии: HttpOnly, Path `/api`, SameSite `lax`, Secure включается при HTTPS;
- небезопасные запросы требуют разрешённый `Origin`;
- секреты и пароль менеджера не хранятся в Git.
- во внешний AI-провайдер отправляется только описание заявки, без имени и телефона;
- AI worker запускается отдельно от web API и безопасно работает с PostgreSQL-очередью;
- защищённые manager endpoints управляют retry и ручной коррекцией; публичный API не раскрывает служебные AI-метаданные.
- n8n вызывает только `/api/internal/notifications/dispatch` по Bearer service token; cookie и браузерный `Origin` для этого machine-to-machine endpoint не используются;
- Telegram token, chat id и service token не хранятся в Git; отключённая/неполная конфигурация не выполняет внешний вызов;
- ссылка менеджера в Telegram строится из `MANAGER_PUBLIC_URL`; `localhost` подходит только на том же компьютере и не откроется на телефоне без отдельно настроенного доступного URL.
